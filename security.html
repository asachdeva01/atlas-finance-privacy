Atlas Finance — Information Security Policy

Covers the application registered with Plaid as “Atlas Core Finance”. Effective September 16, 2026. Owner and accountable person: Abhi Sachdeva (a.sachdeva2021@gmail.com). Reviewed every 12 months or on any material change.

1. Purpose and scope

This policy states how consumer financial data obtained through Plaid and Robinhood is protected in Atlas Finance, a private personal finance application operated by one person for the owner and invited household members. It covers the application, its server, the data store, backups, and the people and devices that can reach them. Companion documents: Privacy Policy and Data Retention and Disposal Policy.

2. Access control policy

2.2 Centralized identity and authentication

  • One identity system: the application's own account store. Each member signs in with a password (argon2-hashed) and a WebAuthn passkey (Face ID / Touch ID), which is phishing-resistant multi-factor authentication.
  • Step-up: connecting a financial institution requires a passkey verification within the previous five minutes. Without a registered passkey the server refuses to start Plaid Link.
  • Network identity: the server is reachable only over Tailscale. Each device holds its own cryptographic node key approved by the owner; there is no public endpoint.
  • Non-human access uses OAuth tokens (Plaid, Robinhood) encrypted at rest; the application never stores bank credentials.

2.3 Zero-trust architecture

  • No implicit trust from network location: the application binds to localhost and is exposed only through Tailscale's TLS proxy; every request must carry a valid short-lived session cookie and a CSRF header.
  • Least privilege by construction: every query is filtered by the requesting user's id; sessions expire (access 15 minutes, refresh 30 days, rotated on use); sensitive actions require step-up authentication.
  • Read-only integrations: the Robinhood integration enforces an allow-list of read tools and cannot place, modify, or cancel orders; Plaid products are limited to Transactions, Investments, and Liabilities.

2.4 Provisioning and de-provisioning

  • Accounts are created only with an invite code issued by the owner.
  • De-provisioning is automated and atomic: deactivating an account revokes every session and passkey and removes every connected institution (Plaid item removal, token deletion, data cascade). It runs automatically for any account with no sign-in for 180 days, and on request for departed household members.

2.5 Periodic access reviews and audits

  • A monthly automated access review lists every account, its factors, live sessions, last sign-in, and institutions; revokes sessions older than 30 days; flags accounts inactive for 90 days; de-provisions at 180. Each review is written to a dated report kept with the application's journal, and recorded in the audit log.
  • All authentication events, connections, disconnections, gate changes, and de-provisioning are written to an append-only audit log with timestamp and source address. Sign-in events are retained 90 days; money-adjacent entries for the life of the account.

3. Data protection

  • In transit: TLS 1.2 or better for every client–server and server–provider connection.
  • At rest: institution tokens encrypted with a server-held key (Fernet); the server disk is fully encrypted (FileVault). Backups are taken nightly, stay on the encrypted disk, and expire after 30 days.
  • Minimization: only the data needed to display the member's own finances is requested or stored. Numbers, never credentials or tokens, are sent to the AI provider that writes reports.

4. Development and vulnerability management

  • Dependencies are scanned weekly (pip-audit for the backend, npm audit for the frontend) by a scheduled job that writes a dated report. Critical and high findings are patched within 7 days, moderate within 30, low at the next release.
  • Runtimes (Python, Node, macOS) are kept on supported, non-end-of-life versions; the operating system auto-updates.
  • All changes are version-controlled; secrets live only in environment files excluded from the repository; the automated test suite runs before each deployment.

5. Incident response

  • On suspected compromise: rotate the Plaid and Robinhood credentials, revoke all sessions, review the audit log, and notify affected members within 72 hours. Plaid is notified through the dashboard support channel.

6. Review

This policy and the evidence it references (access-review and vulnerability-scan reports) are reviewed by the owner every 12 months, and whenever products, integrations, or hosting change.
